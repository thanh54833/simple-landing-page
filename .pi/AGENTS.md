# Guide for agents — pi runtime files

## OVERVIEW
Two generated artifacts and one manifest. Generated: `.mcp/servers.json` → `mcp.json`, `.opencode/command/*.md` → `prompts/*.md`. Manifest: `settings.json` holds the project's pi packages (npm and git sources) and the `subagents` model defaults.

## STRUCTURE
```
.pi/
├── CHANGELOG.md  # root log: settings/packages changes, newest-first per date
├── mcp.json        # verbatim copy of .mcp/servers.json (GENERATED)
├── prompts/        # 8 templates: adr, impeccable, implement, intent, plan, ship, spec, verify (GENERATED)
├── settings.json   # project-scope pi packages: npm:pi-subagents, npm:pi-lens,
│                   #   git:github.com/obra/superpowers@v7.0.0 (CLI-managed)
├── npm/            # install tree for npm packages, ~160 MB, gitignored
└── git/            # checkout tree for git packages, 11 MB, gitignored
```

## WHERE TO LOOK
| Need | Go to |
|------|-------|
| Change a command's steps | `.agents/.commands/<name>.md`, then `make agents_sync` |
| Change an MCP server | `.mcp/servers.json` |
| Add a project MCP server visible to pi | registry, then `make mcp` |
| Understand the generator | `scripts/sync-mcp.mjs`, `scripts/sync-agents.mjs` |
| Add/remove a pi package for this project | `pi install -l npm:<pkg>` / `pi remove -l npm:<pkg>` → edits `settings.json` |
| Pin a subagent model | `settings.json` → `subagents.defaultModel` / `agentOverrides.<name>` — hand-owned, not CLI-written |
| Track history | `CHANGELOG.md` | newest-first per date; update khi đổi `settings.json` packages/model (sync `mcp`/`prompts` không ghi) |
| Use Superpowers process skills (`brainstorming`, `writing-plans`, `systematic-debugging`, TDD, review, subagent dispatch) | `git:github.com/obra/superpowers@v7.0.0` in `settings.json`; 15 skills at `git/github.com/obra/superpowers/skills/` |
| Which packages are actually configured | `pi list` → `User packages` vs `Project packages` |
| Change the provider or default model | `settings.json` → `defaultProvider` / `defaultModel` / `subagents.*`; `opencode-go` is a built-in provider, no `models.json` needed |
| Set the provider API key for this project | root `.env` (`OPENCODE_API_KEY`), then `make pi`; `.env` is gitignored, `.env.example` is the template |

## CONVENTIONS
- Regenerate with `make mcp` / `make agents_sync`; verify with `make mcp-check` / `make agents_sync-check` (`make commands` / `commands-check` still work).
- `prompts/*.md` carry a YAML comment marker (`generated by scripts/sync-agents.mjs from .agents/.commands/…`); body and `$ARGUMENTS` are identical to the router.
- A stale prompt means its router was deleted; `make agents_sync` prunes it, `--check` reports it.
- `settings.json`'s `packages` array is written by `pi install -l` / `pi remove -l`. The `subagents` block (`defaultModel`, `agentOverrides`) is hand-owned model config. The file survives `make mcp` and `make agents_sync` — those only touch `mcp.json` and `prompts/`.
- Provider: `opencode-go` is built-in (`OPENCODE_API_KEY`, model refs `opencode-go/<id>`), already the default here; `pi auth check --provider opencode-go` prints `ready`/`not_ready`. `~/.pi/agent/auth.json` holds stored credentials — the project never commits a key.
- `.env` is not read by pi. `make pi` runs `scripts/pi-env.mjs`, which exports `.env` into the pi process (a variable already set in your shell wins); plain `pi` still authenticates through `auth.json`.
- Project packages load only after **project trust** is granted; `pi -a` approves for one invocation. Global copies under `~/.pi/agent/npm/` load regardless.
- Git-sourced packages clone into `.pi/git/<host>/<owner>/<repo>` (gitignored at the root **and** by its own `.gitignore`); pin the tag in `settings.json` (`@v7.0.0`) so reconciliation stays deterministic. `pi remove -l` prunes the checkout.
- Superpowers stays **project-scoped, one entry only**. Declaring it both user- and project-wide loads the extension twice; a user-level copy is removed with `pi remove git:github.com/obra/superpowers` (no `-l`).
- The Superpowers extension injects a `using-superpowers` bootstrap (`<EXTREMELY_IMPORTANT>`) at session start and after compaction. It competes with `agentic-os/` gates: SDLC gates stay `writing-intent` → `writing-adr` → plan; Superpowers covers execution (TDD, debugging, review, subagents).
- Package tools are resolved at session start: after `pi install`, an already-running session keeps its old tool set. Open a new session to use `subagent`, `lens_*`, etc.
- `pi-lens` 4.4.4 ships `sg.exe` / `ast-grep.exe` inside its tarball; npm still warns `@ast-grep/cli postinstall not covered by allowScripts`. Verified working here (`project_report` answered on this repo), so the warning is inert — if structural rules start failing, allow the script (`npm approve-scripts`) instead of reinstalling.
- pi-lens operates from its own `docs/agent-guide.md` inside `.pi/npm/node_modules/pi-lens/docs/`; read that before driving `lens_*` tools.

## ANTI-PATTERNS
- Don't hand-edit `mcp.json` or `prompts/*.md`; the next `make` overwrites them and the check fails.
- Don't create a prompt without a matching router.
- Don't commit `.pi/npm/` (160 MB of deps, per-machine) or `.pi/git/` (11 MB checkout) — both gitignored; `settings.json` is the file worth committing.
- Don't run `npm install` inside `.pi/npm/` by hand; `pi install -l` owns that tree and reconciliation.
